## What it is, in two sentences

CodeFronts Motion is a catalogue of 41 hand-written collections of CSS animations (loaders, text effects, hover effects, keyframe animations, background and scroll effects, page transitions), each collection holding 10 to 36 numbered demos with copy-ready HTML and CSS and, in some cases, a few lines of JavaScript. The site's pitch is no framework and no library dependency, and it labels each demo as pure CSS, light JS, or CSS + JS, which is a useful first filter for us.

## Techniques this source points to

For each technique, one paragraph: what it is, how it is done in plain terms, a first opinion on the rig questions (seekable, deterministic, offline, tokens, cost, plain files) marked as **unmeasured** unless a study exists, and the study it links to in `studies/` if there is one.

**Stepped typing (typewriter).** The text is already in the page; the visible width of its box grows one character at a time using a stepped timing function, and a separate looping animation blinks the caret. Everything is a CSS keyframe animation, so it should be pausable at any time offset with the Web Animations API and should render the same frame every time. Monospace or a fixed character width is needed for the width trick to line up. Rig questions: **unmeasured**. No study yet.

**Staggered text entrance (word, letter and line reveals).** Each word, letter or line is wrapped in its own element and hidden by an overflow mask; a shared keyframe animation slides or fades each one in, with a delay that grows by index. Pure CSS, declarative timing, and nothing random, so seeking should be exact. Splitting text into spans has to be done at build time or by a small deterministic script. Rig questions: **unmeasured**. No study yet.

**Self-drawing outlines.** Text or a diagram is an SVG path with a dashed stroke; the dash offset is animated from the path length to zero so the line appears to be drawn. This is the same stroke-dash idea as the classic CodePen line-drawing demos and depends only on CSS or SVG animation. Good fit for diagram scenes and concept openers. Rig questions: **unmeasured**. No study yet.

**Counters driven by a registered custom property.** A numeric custom property is declared with a type so the browser can interpolate it, a keyframe animation moves it from start to end, and a CSS counter prints the rounded value as text. The progress ring variant drives a dash offset from the same property, so the number and the ring cannot drift apart. Pure CSS, no script, so seeking should be exact; the odometer variant reaches the same result with clipped digit strips. Rig questions: **unmeasured**. No study yet.

**Panel transitions (fade, slide, scale, wipe, blur, page turn, curtain).** Two scenes are stacked; the outgoing and incoming panels animate opacity, transform, clip path or blur over the same duration. The six CSS-only patterns in the page transitions collection are the plainest set of scene transitions in this catalogue. The page turn needs preserve-3d and a perspective on the parent. Rig questions: **unmeasured**. No study yet.

**Flip and split-flap reveals.** A card or digit is two half faces rotated in 3D about a shared hinge, with a shadow that darkens at mid-turn. The text version can cycle words; the digit version can count. The CSS parts are deterministic; the demos that use a script to advance the value would need that script replaced by the rig's clock. Rig questions: **unmeasured**. No study yet.

**Shimmer skeletons.** A light gradient is animated across grey placeholder blocks by moving its background position on a loop. Useful as a loading state inside a mocked product screen, and trivial to pause. Rig questions: **unmeasured**. No study yet.

## Not for us, and why

- **Every scroll-driven demo as shipped** (scroll-driven text reveal, sticky scroll fade, parallax text, scroll-triggered counters, scroll progress bars, image reveal on scroll, the whole animation-timeline collection): the animation is bound to scroll position, and footage has no scroll. The visual could be rebuilt on a time-based timeline, but the demo itself is not seekable by time.
- **Pointer-driven demos** (perspective tilt on mousemove, cursor-held spotlight, proximity-mapped variable font weight, all hover collections): they need a live pointer, which has no meaning in footage unless the rig scripts the pointer. Only the self-panning or autoplay variants are candidates.
- **Text unscramble, script version**: the letter shuffle is random at run time, so two renders will not match. The CSS slot-reel variant is fine.
- **Ink Bleed, Triangle Shatter, ASCII Matrix Rain, Paint Brush Stroke** (page transitions 7, 8, 10, 11): canvas drawn by script with noise, physics or random characters. Not reproducible frame for frame unless the randomness is seeded and the loop is driven by the rig's clock rather than real time, and none of that is shown.
- **Counters that fetch or simulate live data** (live stock and sales counter, live visitor widget, stock ticker, fundraising meter, countdown timers using the real clock): built around changing input or the wall clock; a video needs a fixed script of values.
- **Number counter collection as a code source** until its item pages show a licence: that page carries no licence statement, so it is notes and links only for now, even though sibling pages say MIT.
- **Affiliate and product-styled demos** (branded SaaS, fintech and gaming mockups): the styling is generic, but our rule is never to recreate a third-party product, so take only the mechanism, never the look of a named product.
- **Anything labelled Tailwind**: nothing wrong with the licence, but it adds a build layer we do not want in a plain-files rig; the plain CSS twins of the same collections exist and are the ones to read.
