# Define the term in the breath it is named

Group: argument. Say it like: "define as you go", "what is X", "explain the acronym", "situation, failure, definition, example".

## Observed

- Stephane Maarek (10JKpg-eqZU): three nested definitions in one sentence ("Route 53 is a managed DNS, and DNS stands for Domain Name System, and what's the DNS overall? Well it's a collection of rules and records..."), then an image to hold it; every technical noun is followed within one clause by what it is or does.
- AWS Developers (FAgmR9VV0GQ): inference, tool use, RAG, embedding, vector, agent are each defined at the moment first needed by the same pattern: situation, failure or need, definition, examples ("X, that's tool use. Y, also tool use. Z, you got it. Tool use"), mechanism as a numbered sentence.
- Fireship (I_KVMFrUtPk): nothing is defined except the one new thing (the military model), because the viewer is assumed to know the rest.

## The numbers

Maarek: 660 words, "so" 18 times, three self-asked questions answered at once. AWS: four terms, each by the five-step pattern. IBM: nothing defined except by example; "agentic" used without a gloss.

## The effect

A term defined where it is first used costs one clause and never a section; the learner is never carrying an undefined word. The AWS pattern (need first, then the name) makes the definition the answer to a question the learner just felt.

## Counter-example

Fireship and Casually assume everything and define nothing, which is right for an in-group audience and wrong for a learner; Ken Burns gives a proper noun once with a gloss and never again.

## What it needs

A narration rule (the term, what it is, what it does, in one sentence) and a storyboard column for the term each scene introduces.
